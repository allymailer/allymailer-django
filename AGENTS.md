# AGENTS.md

AllyMailer Django — Django integration of the AllyMailer Python SDK (``) for the AllyMailer transactional email Web API (Web API 1.90).

## Working on this repository

- **Generated code.** The whole package is generated by the AllyMailer team from the AllyMailer Web API OpenAPI spec (Web API 1.90): sources, docs, README.md and this file. Do not hand-edit it: the next release replaces the content of this repository. Report problems and requests in the issues of this repository (https://github.com/allymailer/allymailer-django).
- **Build and check:**

  ```bash
  python -m pip install -e .
  ```

- **Source label.** Every request carries the query parameter `platform=django.1.1.1,python-sdk.1.1.1` (this package, then the SDK it is built on).
- **Tests.** Before a release the generator installs the package into a test app of Django and checks the client, the webhook endpoint and the mailer against a mock of the API: no real API key, no real sends.
- **Release.** The version (1.1.1 in pyproject.toml) and the tag `v1.1.1` come from the generator; README.md states the Web API version the release was generated from.
- **Secrets.** Never commit API keys; the examples read `ALLYMAILER_API_KEY` from the environment.

## Integrating AllyMailer with this package

Full guide: [README.md](README.md). Django integration of the [AllyMailer Python SDK](https://github.com/allymailer/allymailer-python-sdk) (``): the API client in the settings (`get_client()`), a webhook endpoint with signature check, a Django email transport that sends through `email/send`.

Install:

```bash
pip install allymailer-django
```

Requirements: Python 3.8+, Django 4.2+.

Rules that generated code must follow:

- Server-side only. Read the API key from `ALLYMAILER_API_KEY`; never put it in browser or mobile code, never commit it.
- Base URL `https://cp.allymailer.com/ua/transactional/api/v1`; every method is POST with a JSON body; auth header `X-API-KEY`. The package does all of it.
- First email without DNS: `domain/get-sandbox-domain` → `confirmed-email/create` (the user clicks the link within 48 hours) → `email/send` from `noreply@<sandbox-domain>` to the confirmed address. Account API key only; up to 10 confirmed addresses, 100 emails a day; the domain expires after 31 days.
- Never ship a sandbox domain as the production sender (it is not in `domain/list`); read `from_email` from config. Production needs a verified domain: `domain/get-dns-records` → DNS records → `domain/validate-verification-record`, `domain/validate-dkim` → `domain/list`.
- Set `message.idempotence_key` on retryable sends; retry network errors, `429` and `5xx` with backoff, not other errors unchanged. Up to 500 recipients and 10 MB per request with the attachments in base64 (a third larger than the files); always `body.html` or `body.plaintext`.
- Delivery events via webhook (`webhook/set`), not polling; the webhook endpoint of this package checks the `auth` signature of every notification.
- Keep the default unsubscribe and tracking behaviour; changes go through AllyMailer support.
- Do not invent methods or fields. Check the [README](README.md), the [API reference](https://docs.allymailer.com.ua/ua/web-api-ref) or [llms.txt](https://docs.allymailer.com.ua/llms.txt).

### Configuration

The API key goes to `ALLYMAILER_API_KEY`.

```python
# settings.py
INSTALLED_APPS = [..., "allymailer_wrapper"]

ALLYMAILER = {
    "API_KEY": os.environ["ALLYMAILER_API_KEY"],
    "HOST": "cp.allymailer.com",  # optional
}
MAILERS = {"default": {"BACKEND": "allymailer_wrapper.mail.EmailBackend"}}  # Django 6.1+
# EMAIL_BACKEND = "allymailer_wrapper.mail.EmailBackend"                    # Django < 6.1
DEFAULT_FROM_EMAIL = "Shop <shop@example.com>"

# urls.py
urlpatterns = [..., path("allymailer/", include("allymailer_wrapper.urls"))]  # /allymailer/webhook
```

| Option | Environment variable | Default | Description |
|---|---|---|---|
| `ALLYMAILER["API_KEY"]` | `ALLYMAILER_API_KEY` |  | User or project API key (required). |
| `ALLYMAILER["HOST"]` | `ALLYMAILER_HOST` | `cp.allymailer.com` | API host (datacenter: `cp.allymailer.com`) or a full base URL. |
| `ALLYMAILER["TIMEOUT"]` | `ALLYMAILER_TIMEOUT` | `30` | Request timeout, seconds. |
| `ALLYMAILER["WEBHOOK_KEY"]` | `ALLYMAILER_WEBHOOK_KEY` |  | API key the webhooks are signed with (the key of the user/project of the webhook), if it differs from the API key. |

### Sending mail

Messages of the Django email go through [email/send](https://docs.allymailer.com.ua/ua/web-api-ref#email-send): from, to/cc/bcc, reply-to, subject, HTML and text parts, attachments, inline images and `X-*` headers.

```python
from django.core.mail import EmailMultiAlternatives, send_mail

send_mail("Order shipped", "Your order is on its way", None, ["user@example.com"])

message = EmailMultiAlternatives("Order shipped", "Text", to=["User <user@example.com>"], headers={"X-Order": "42"})
message.attach_alternative("<b>HTML</b>", "text/html")
message.tags = ["orders"]                 # -> tags
message.metadata = {"order_id": "42"}     # -> global_metadata
message.send()
print(message.job_id)
```

### Webhooks

The endpoint answers `GET` with 200 OK (the URL check of [webhook/set](https://docs.allymailer.com.ua/ua/web-api-ref#webhook-set)) and accepts the `POST` notifications: it checks the `auth` field (MD5 of the request body in which the `auth` value is replaced by the API key), answers 401 to a wrong signature, and passes the notification and each of its events to the application.

```python
from django.dispatch import receiver
from allymailer_wrapper.signals import webhook_event_received


@receiver(webhook_event_received)
def on_event(sender, event, user, **kwargs):
    data = event.event_data
    print(event.event_name, data.email, data.status)
```

Register the URL of the endpoint with `webhook/set`, e.g. `https://example.com/allymailer/webhook`.
